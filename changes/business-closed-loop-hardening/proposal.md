# 业务闭环完善

## Why

现有 FastAPI + MySQL 服务已经能够展示账号、商品、SKU 和 Listing，但巡检发现看板仍显示 SQLite，`/api/stats` 与看板商品数量口径不一致，269 条 Listing 中有 45 条处于 `copy_missing` 且标题为空，账号 API 状态仍为 `none`。外部 TikTok、AI、飞书和 CDP 集成如果缺少凭据或运行环境，必须明确反映不可用，而不能以模拟成功状态继续流程。当前状态会让运营人员误判系统是否可以安全进入真实上架。

## What Changes

- 统一看板和统计 API 的 active 商品统计口径，并修正 MySQL 产品标识。
- 建立可追踪的文案生成/补文案流程，保留缺文案时的安全阻断。
- 让图片质检、审批、导出和上架准备使用一致的准入门禁。
- 为 TikTok、AI、飞书、CDP 集成补充真实适配器状态、凭据检查、超时/失败诊断和可观测结果。
- 增加接口、流程和真实失败场景的测试与运行验证。

## Scope

### In

- FastAPI 路由、看板模板、统计查询、Listing 生命周期。
- 文案生成端口及真实/不可用状态处理。
- 图片质检、审批、导出和上架前准入规则。
- TikTok、AI、飞书、CDP 集成边界的真实状态报告。
- MySQL 数据读写、现有迁移结果和回归测试。

### Out

- 不伪造任何外部服务成功。
- 不绕过平台风控、审批或图片/违禁词规则。
- 没有真实凭据时不承诺实际发布；真实账号开通、密钥申请和外部网络环境不由代码变更代替。
- 不重新设计已完成的 SQLite→MySQL 迁移基础设施，除非闭环验证发现兼容性缺陷。

## Impact

影响 `app/routers`、`app/templates`、`app/application`、`app/integrations`、`app/agent`、导出脚本、配置和测试。数据库 schema 只有在现有生命周期状态不足以表达真实集成结果时才扩展，并必须提供 Alembic 迁移。

## Proof of Completion

- API 与看板统计口径一致，页面明确使用 MySQL。
- 缺少文案、凭据或运行环境时均有可断言的非成功状态和诊断信息。
- 导出结果只包含通过全部准入门禁的记录。
- 在无外部凭据环境中，测试证明系统不会伪造 TikTok、AI、飞书或 CDP 成功。
- 既有测试、MySQL 健康检查、数据完整性检查和新增端到端验收全部通过。
