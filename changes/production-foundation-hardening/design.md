# 设计：飞书运营控制面与持久化执行层

## 事实与约束

- 当前飞书多维表格已实现“待上架→处理中”的领取、批次冷却和超时锁扫描。
- `tasks` 已有状态、租约、尝试次数和 JSON state 字段，但新版 API 使用内存 `TaskService`，与 MySQL worker 未接通。
- 审批状态存于进程内字典，当前部分审批抽样逻辑仍读取 SQLite。
- 真实外部服务不能被假定可用；发布约 50 件测试商品属于高影响外部操作，必须晚于非发布连通验证和独立人工批准。

## Goals

- 让数据库成为任务、审批和发布尝试的唯一事实源。
- 让飞书多维表格成为清晰、可恢复、可审计的运营界面。
- 防止重复发布、丢失审批、静默卡死与敏感日志泄露。

## Non-goals

- 不新增自建运营前端。
- 不改变现有商品业务规则或绕过发布门禁。
- 不在本期内把真实发布自动化为无人批准的批处理。

## Decisions

### 1. 数据库优先，飞书投影

**Choice**：MySQL 任务、审批和审计记录先完成状态转换，再把结果投影回飞书；飞书的 record_id、批次号和版本/更新时间写入任务 state。

**Rationale**：飞书接口、网络和进程均可能失败，不能承载唯一状态。数据库允许恢复、并发控制和完整审计。

**Alternatives**：以飞书单元格为唯一状态；或双向任意覆盖。前者无法安全原子领取，后者会产生冲突覆盖。

**Consequences**：需要补充任务字段/审批审计迁移，并将飞书回写设计为可重试的幂等投影。

### 2. 受控飞书表结构

**Choice**：保留现有选品表和上架表；上架表增加或校验 `任务ID`、`任务批次`、`状态`、`状态原因`、`锁定时间`、`尝试次数`、`批准人`、`批准时间`、`发布结果`、`外部追踪ID`、`下架方案` 字段。

**Rationale**：运营人员可在单一表面看到可操作状态和可追溯结果，程序可用稳定字段完成映射。

**Alternatives**：为每次运行新建表或只通过飞书消息卡管理。新建表降低跨批次可见性；消息卡不适合批量状态与重试。

**Consequences**：启动诊断必须校验字段，并以迁移指引补齐缺失字段，禁止静默降级。

### 3. 原子领取和租约恢复

**Choice**：Repository 在 MySQL 事务中用条件更新或 `SELECT … FOR UPDATE SKIP LOCKED` 领取 pending/过期租约任务；每个外部动作使用稳定幂等键。

**Rationale**：现有普通 select 后提交在多 worker 下会重复领取。租约允许进程崩溃后安全恢复。

**Alternatives**：仅靠进程内锁或飞书“处理中”状态。两者均无法跨进程保证唯一性。

**Consequences**：SQLite 单元测试保留为契约测试，新增 MySQL 集成测试覆盖并发与租约。

### 4. 四段真实联调与发布门

**Choice**：按飞书→AI→CDP→TikTok 分段执行非发布健康验证，记录 confirmed/failed/unavailable；确认结果默认 24 小时有效，凭据、端点、账号或市场配置变化立即失效。四项均满足有效窗口后才允许生成测试发布批准卡。人工批准后，worker 将最多 50 件逐件提交并回写。

**Rationale**：把连通问题与发布问题分离，避免凭据缺失或浏览器异常时误发布。

**Alternatives**：一次性直接跑发布，或只检查配置。前者副作用不可控，后者不能证明真实可用性。

**Consequences**：需要人为决定测试账号、市场分布和下架策略；这些内容作为批准卡/表格字段的必填项。

### 5. 只读诊断页与日志脱敏

**Choice**：保留本地页面，但仅输出安全指标和失败摘要；统一结构化日志脱敏器，默认拒绝记录 token、secret、signature、原始回调和完整用户标识。

**Rationale**：本地诊断保留排障价值，同时消除与飞书运营面重复的控制入口。

**Alternatives**：删除页面或保留现有全量明细与控制按钮。前者降低故障排查效率，后者扩大敏感数据暴露面。

**Consequences**：运维文档必须描述如何通过任务 ID 和飞书 record_id 做关联排障。

## Risks and Verification Evidence

| 风险 | 缓解 | 证据 |
|---|---|---|
| 重复发布 | 原子领取、幂等键、批准上限 | MySQL 并发测试、重复回调测试 |
| 飞书回写失败 | 数据库先提交、投影可重试 | 回写失败后恢复测试 |
| 外部服务假阳性 | confirmed 仅来自真实探针 | 无凭据/超时/成功探针记录 |
| 50 件发布影响扩大 | 独立批准卡、上限校验、逐件回写 | 批次超限测试、批准审计 |
| 日志泄密 | 集中脱敏和负向断言 | 日志捕获测试 |
