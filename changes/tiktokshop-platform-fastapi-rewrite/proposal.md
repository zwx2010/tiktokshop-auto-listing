# TikTokShop Platform Lite FastAPI 分层重构

## Why

现有项目虽然使用 FastAPI 和 SQLAlchemy，但应用启动、飞书多维表轮询、审批回调、CDP 流程和数据库访问集中在少数模块中，后台线程直接承载业务编排，SQLite 仍是默认运行时数据库，历史字段补丁依赖启动时 `ALTER TABLE`。这使多账号并发、事务边界、失败重试、迁移和自动化测试都难以稳定演进。项目已有 MySQL 8.0 Schema 设计文档，但代码尚未按该目标落地。此次变更将以分层重构方式重新组织 FastAPI 应用，并完整保留现有运营闭环。

## What Changes

- 建立清晰的 API、应用服务、领域状态机、基础设施和集成适配层。
- 重新设计 REST API、请求响应模型、错误格式、鉴权/签名入口和任务触发入口。
- 使用 MySQL 8.0/InnoDB/utf8mb4 作为唯一运行时业务数据库，金额使用定点数，连接池和事务由应用统一管理。
- 将现有 19 张目标业务表及必要索引、约束落地为可迁移 schema，并提供 SQLite 到 MySQL 的可重复迁移工具和校验报告。
- 将采集入库、清洗定价、三语文案/RAG、图片质检、审核、飞书、多维表轮询、CDP 上架、导出和看板接入新的应用服务与任务系统。
- 增加健康检查、结构化日志、任务日志、幂等控制、失败重试和关键链路自动化测试。

## Scope

### In

- `app/` FastAPI 应用、SQLAlchemy 模型/Repository、业务服务、任务编排和外部集成适配。
- `scripts/`、`tools/` 中直接使用数据库会话的入口迁移到新的应用服务/CLI 边界。
- `app/templates/` 看板所需 API 和页面调用适配。
- `config/` 数据库连接、密钥、运行模式和任务配置约定。
- SQLite 全量数据迁移到 MySQL，包括账号、商品、SKU、Listing、任务、审批相关数据及可识别的历史表资产。
- 测试、迁移说明、启动/健康检查和部署文档。

### Out

- 不删除任何已确认的业务能力或外部集成。
- 不把 SQLite 保留为生产读写后备库；SQLite 仅作为迁移输入和离线 RAG 语料输入（若该索引仍适用）存在。
- 不在本变更中扩展新的第三方平台或新的商品类目。
- 不以兼容旧 API 为约束；旧调用方由本变更同步升级。

## Impact

- 数据层：`app/database.py`、`app/models.py`、新增 migration/迁移工具和 MySQL 配置。
- 应用层：`app/main.py`、`app/routers/`、`app/pipeline.py`、`app/agent/`、`app/feishu/`、`app/rag/`。
- 运行方式：启动、轮询和后台任务不再依赖 FastAPI 入口中的不可控守护线程。
- 运维：需要 MySQL 8.0 数据库、连接串、迁移前备份和迁移校验报告。

## Proof of Completion

完成标准是：MySQL 新库可初始化，现有 SQLite 数据可重复迁移且校验通过；核心 API、后台任务、飞书审批、多维表触发、RAG/文案、图片质检、导出和 CDP 上架链路均有可执行测试或真实环境验证记录；应用可通过统一配置启动并通过健康检查；任务失败可重试、可审计且不会重复上架。
